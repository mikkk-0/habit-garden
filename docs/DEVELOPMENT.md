# Как устроен «Сад привычек»

Этот документ — карта проекта для следующего изменения кода. Установка и повседневное использование описаны в [README](../README.md).

## Путь данных

```text
Qt: окно и трей (desktop.py)
    └─ QWebEngineView → HTML, CSS, JavaScript (static/)
                         └─ HTTP API на 127.0.0.1:8765 (server.py)
                              ├─ HabitStore (db.py) → SQLite
                              ├─ HabitOrder (order.py) → локальный JSON
                              └─ ReminderScheduler (reminders.py) → notify-send
```

- `desktop.py` запускает один экземпляр приложения. Повторный запуск показывает уже открытое окно через локальный сокет Qt. При закрытии окна остаётся трей, а WebEngine освобождается до следующего открытия.
- `static/app.js` хранит состояние интерфейса в памяти, вызывает API и перерисовывает карточки и календарь. Дата «сегодня» приходит от сервера; открытый интерфейс обновляется после полуночи и при возвращении к окну.
- `server.py` отдаёт статические файлы и JSON API. Сервер слушает только `127.0.0.1`; изменяющие запросы должны иметь `Content-Type: application/json`, а чужой `Origin` отклоняется.
- `db.py` владеет соединением с SQLite и проверяет входные значения. `domain.py` отдельно считает статистику по датам, без Qt и HTTP.
- `order.py` хранит только последовательность ID карточек в `~/.config/habit-garden/order.json` (или в `HABIT_GARDEN_ORDER`). При перестановке файл заменяется атомарно; новых заданий, которых ещё нет в списке, интерфейс показывает первыми. Архивные и активные карточки используют один общий порядок.
- `reminders.py` ждёт ближайшего напоминания или сигнала об изменении задания. Для поправок системных часов ожидание ограничено одним часом.

## База данных

По умолчанию файл находится в `~/.local/share/habit-garden/habits.db`. Путь можно задать переменной `HABIT_GARDEN_DB`; каталог данных — переменной `XDG_DATA_HOME`. SQLite работает в режиме WAL. Рабочую базу не следует добавлять в Git.

| Таблица | Что хранит |
| --- | --- |
| `habits` | ID, название, дата создания, архив, выбранный эмодзи, время напоминания и дата последнего уведомления |
| `completions` | Только выполненные дни: пара `(habit_id, day)` — первичный ключ |

Пустые дни не записываются. В старых базах могут оставаться колонки `symbol_off` и `symbol_on`: они больше не используются, но сохраняются ради совместимости. При открытии старой базы без `label_emoji` колонка добавляется автоматически.

Статистика вычисляется при чтении. `total_days` включает день создания и сегодня; `completion_percent` — округлённая доля выполненных дней. Стрик идёт до сегодня, если сегодня отмечено выполнение, иначе до вчера. Отметить дату до создания задания или в будущем нельзя. Архив не стирает историю.

## Локальный API

Все даты имеют вид `YYYY-MM-DD`, время — `HH:MM` по местному времени компьютера. Изменяющие запросы принимают JSON. Ошибки возвращаются как `{"error": "..."}`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Проверка работающего процесса |
| `GET /api/tasks` | Все задания и сегодняшняя дата |
| `PUT /api/order` | Сохранить локальный порядок: `{"ids": [1, 2, 3]}` со всеми ID заданий |
| `POST /api/tasks` | Создать задание: `name`, необязательные `label_emoji`, `reminder_time` |
| `GET /api/tasks/{id}` | Одно задание со статистикой |
| `PATCH /api/tasks/{id}` | Изменить `name`, `label_emoji`, `reminder_time` или `archived` |
| `GET /api/tasks/{id}/month?year=2026&month=10` | Список выполненных дат месяца |
| `PUT /api/tasks/{id}/days/{date}` | Поставить или снять отметку: `{"completed": true}` или `false` |

Эмодзи принимаются только из встроенного каталога `static/emoji-catalog.json`. Каталог создан скриптом `scripts/build_emoji_catalog.py`; источники и лицензии указаны в [README](../README.md) и [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md).

API рассчитан на локальное приложение и не имеет учётных записей или синхронизации. Для мобильного клиента можно повторно использовать правила дат и формат данных; прямой доступ к этому локальному серверу с телефона не предусмотрен.

## Напоминания

Для каждого активного невыполненного задания в `habits.reminder_time` хранится своё время. Когда оно наступает, хранилище атомарно проставляет `last_notified_on`, после чего `notify-send` показывает уведомление. Поэтому за один день задание уведомляет не более одного раза, в том числе после перезапуска. Если приложение запустили позже назначенного времени, сегодняшнее напоминание отправляется при запуске. При изменении задания или отметки API будит планировщик.

## Где менять функциональность

1. Новое постоянное поле задания: добавьте колонку и миграцию в `db.py`, проверку значения и тест старой базы.
2. Новое действие: добавьте маршрут в `server.py`, затем вызов и отображение в `static/app.js` и `static/index.html`.
3. Новое правило статистики: измените `domain.py` и тесты дат в `tests/test_domain.py`.
4. Изменение напоминаний: проверьте выбор следующего времени и защиту от повторов в `db.py`, цикл ожидания в `reminders.py` и `tests/test_store.py`.
5. Порядок карточек меняется в `order.py` и `static/app.js`; колонки для него в SQLite нет.

Тесты запускаются из корня репозитория:

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

`test_ui.py` и `test_desktop.py` используют графический Qt и требуют доступного дисплея; остальные тесты запускаются без окна и используют временные базы данных.
